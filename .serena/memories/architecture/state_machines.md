# State-machine boundaries
- First-party scope: packaged CLI/manager/manifest/scheduling code, benchmark clients, and stop-job automation. Exclude vendored internals/generated artifacts; a conditional or validation pipeline alone is not an implicit FSM. Identify observed/desired state, guards, side effects, completion and failure exits; prefer targeted fixes over generic FSM or persistence frameworks.
- SDK 0.1.15 documents 17 deployment states, including EDIT_*, warm-pool and failed-deletion states. Its status catalogue (bundled METADATA usage-filter documentation) is not an action-permission matrix. The five CLI list filters are not the full catalogue. Preserve dispatch for recognized statuses instead of inventing action bans; recheck SDK evidence on upgrades.
- `DeploymentManager._lifecycle_status` rejects missing/unrecognized status. Start no-ops on DEPLOYED/PENDING; stop no-ops on STOPPED. Restart intentionally submits each time. Start/stop/restart refuse DELETED; deleting an already-deleted UUID is read-only. Real provider acceptance of other recognized states is not established by a localhost fixture.
- Delete preflight reads identity, status and health before the organization-scoped mutation; output includes minimal `before_delete`. Accepted deletion does not prove terminal state or GPU release.
- Readiness is deployment status plus health, not status alone. Env saved/read-back verification and healthy rollout verification are different phases; `mem:ops/environment_updates` owns detailed env rules.
- `schedule set/daily/clear` persist native replica cron configuration. `schedule reconcile` is finite current-time start/stop reconciliation. `schedule run` recomputes current time, reconciles, optionally waits, then sleeps/retries. Keep these mechanisms distinct; preserve overnight/DST/wake catch-up behavior.
- Manifest fields validate before API calls. Unique-name/detail/config preflight precedes repository creation. Malformed listings and unavailable details after a matched ID must fail closed, never mean absent or trigger replacement. Resume compares repository/command and explicitly requested fields when reported; do not invent provider payload normalization.
- Multi-resource creation, env updates and sequential fail-fast batches are not atomic. Earlier side effects may survive failure; inspect before retry. No incidental automatic rollback, destructive cleanup or delete/recreate.
- Benchmarks use positive counts and bounded workers at fixed concurrency, not a capacity search. SSE completion requires [DONE]; EOF, malformed data or in-band errors fail, even after full usage. Do not echo raw in-band error payloads.
- Stop-job lock spans discovery through CLI completion and releases on process exit; no external flock dependency on macOS. Listing/parsing errors must not look like an empty successful run. Preserve the overnight guard; operational setup is in `mem:ops/local_auto_stop`.

# Verification boundaries
- Permanent test selection is in `mem:conventions`; completion workflow is in `mem:task_completion`. No live deployments merely to verify guard logic.
- Real SDK/CLI to localhost proves local guards, HTTP dispatch, result shaping and failure propagation, not provider transition permissions, GPU release or live readiness. Isolated shell scenarios prove job locking/time guards; local benchmark HTTP scenarios prove SSE/concurrency paths. Disclose tokenizer/prompt fixture substitutions; they do not validate real tokenizer/model behavior.
- Help/startup checks cannot prove changed behavior. Remove throwaway harnesses before commit; do not retain fake SDK/manager or private-helper assertion matrices as permanent regression suites.
